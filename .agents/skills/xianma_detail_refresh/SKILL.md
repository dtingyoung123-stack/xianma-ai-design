# AI 商详焕新

本 Skill 的目标是向平台返回一组达到要求的商品详情图，不是只生成单张好看的图片。调用本 Skill 即视为用户已授权本次任务所需的素材处理、模型调用、结果落盘和测试动作，不再增加额外授权确认步骤。

## 模式选择

- `preserve_product`：主体不变。原图是商品事实源，只调整人物、背景、场景、光线、构图和视觉系统。
- `replace_product`：主体替换。新主体参考图是唯一商品事实源；原详情图只提供详情角色、文案、版式和场景语义，不得继续作为商品外观依据。

## 固定流程

1. 读取项目规则、当前 PRD 和输入素材；确认图片数量、顺序、角色、文案和商品来源。
2. 生成结构化任务数据，明确模式、商品不可变事实、组级视觉系统和逐图任务。
3. 只生成一次组级视觉系统，并把主色占比、服装、背景、标签和禁止风格写成可检查的规则。
4. 先生成一张风格锚点图并由 AI 自动检查；合格后，其余图片在支持多图参考时传入该锚点，并明确它只提供风格、不提供商品、人物和文案。不得要求运营确认中间结果。
5. 按原顺序逐张生成；每张独立传入必要的原图与商品参考图，不依赖模型记忆上一张。版式源只提供结构和语义，不继承其旧配色与装饰。
6. 单次 API 成功只得到内部候选图；对每张执行商品、物理贴合、文案、角色和版式检查，再做整组一致性检查。
7. 只有全部质量项通过的图片，才按对应原图尺寸归一化并作为成功结果返回平台；比例不一致时停止并返修，不拉伸交付。平台下载、点赞和单图编辑继续使用现有规则，互不作为前置条件。
8. 质量失败时保留内部候选和失败证据，只重试当前图片并记录失败类型、修改段落和版本，不整组盲目重生成；每张最多自动重试 3 次，达到上限后返回该图片失败。
9. 保留原图、提示词、模型、任务 ID、原始候选、质量记录和重试快照。

## 关键实现边界

- 结构说明、尺码表、卖点标签、Logo、箭头和参数优先采用后置合成或确定性渲染；模型主要生成商品、人物、场景和光影。
- 文字、数字、Logo 或连接线优先采用后置合成或确定性渲染；由模型重新绘制时必须由 AI 逐字逐项检查，不增加独立的运营确认步骤。无法确认正确时判定质量失败并重试。
- 模型返回尺寸不是交付尺寸事实源。使用对应原图的宽高做确定性缩放或画布合成，并保留未处理的模型原图。
- 单次接口成功不等于平台生成成功；只有内部质量检查通过后才能返回成功结果，不得因候选文件已落盘而放行。
- 整组一致性是内部硬门禁。明显偏离组级主色、服装、背景、字体、标签或空间家族的单图必须重试。
- 主体替换必须同时写出新主体的正向材质/结构事实和旧主体的具体排除项。
- 画面中的“视角、商品位置、接触关系、遮挡和阴影”必须明确，不能只写“自然融合”。
- 用户提供的文案和数字逐字保留，不允许模型润色、翻译、增删或臆造。
- 组图数量、顺序、详情角色和尺寸一一对应；正常成功时向运营返回完整组图，异常时沿用平台现有部分成功或失败状态。

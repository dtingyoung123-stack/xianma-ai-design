## 1. 需求背景与目标

### 1.1 当前问题

`/admin/data` 已展示管理关注项四张指标卡，但当前数值为前端模拟数据。上位 PRD 已定义四项指标的名称、基本公式和相关事实对象，但 `managementFocus` 尚未形成独立、完整的子字段契约，研发仍需要自行在多个章节之间拼接以下信息：

- 哪些事件来自 2026-07-27 旧埋点需求；
- 哪些旧事件需要补字段、补成功时机或补稳定关联；
- 哪些事实属于本期新增；
- 指标如何按时间、组织、功能和权限取数；
- 结果、创作链、资产、任务和积分如何串联；
- 数据不完整、重复、延迟或分母为 0 时如何处理。

### 1.2 本次目标

- 让研发把本 Markdown 与目标前后端仓库交给 Codex 后，可以定位现有实现并完成最小范围开发。
- 让四项指标的页面值、说明、分子、分母、明细和专题页使用同一统计口径。
- 明确历史组织归属、后续行为延迟更新、跨任务判定、净积分和幂等去重规则。
- 保持管理判断边界：只展示事实，不自动判定异常、浪费、低效或人员绩效。

### 1.3 成功判断

- 四项指标均能追溯到具体任务、结果、成功后续行为、资产使用事实或积分结算事实。
- 同一查询条件下，管理关注项与资产、任务效率、积分专题中的对应指标完全一致。
- 同一业务动作重复投递不会重复计数；前端点击成功前不会进入核心指标。
- 数据链路未验收时返回 `NOT_READY` 或 `null`，不使用模拟数据或 `0` 伪装可用。
- 系统管理员、主管和部门管理员只能看到当前服务端授权范围内的聚合数据。

## 6. 核心指标规则

### R-01 产出后续使用率

- **指标解读**：观察平台成功产出中有多少真正进入后续工作，而不是停留在生成和预览阶段。
- **成功结果分母**：所选时间、组织和功能范围内，`result_status=SUCCESS` 的去重 `result_id`。
- **后续使用分子**：上述成功结果中，截至 `dataAsOf` 至少发生一次成功后续行为的去重 `result_id`。
- **成功后续行为**：下载、继续编辑、加入素材库、认可、复制文本、导出文本、跨任务复用。
- **公式**：`followupUseRate = followupUsedResults / successfulResults`。
- **去重**：同一结果发生多个动作仍只计 1 个后续使用结果；动作次数可以保留但不进入本指标分子。
- **排除**：结果预览、按钮点击但执行失败、取消动作、失败结果、审核失败结果、无后续行为结果。
- **延迟更新**：结果生成后在未来发生成功后续行为时，原生成周期的分子允许自然更新；接口必须更新 `dataAsOf`。
- **空值**：`successfulResults=0` 时 `followupUseRate=null`。

### R-02 首轮直接采纳率

- **指标解读**：观察用户是否在首次业务提交产生的结果中直接获得可继续使用的内容。
- **创作链创建**：没有来源任务、来源结果或来源历史的首次提交创建新的 `creative_chain_id`，`round_index=1`。
- **创建失败**：只有 `task_created` 成功后才形成业务轮次；`task_submit_click` 后任务创建失败不创建创作链或轮次，之后第一次成功创建的任务仍为首轮。
- **上下文判定**：不得比较提示词或素材内容判断新旧创作。空白入口或用户明确重置创作上下文后的提交创建新链；当前创作上下文未重置时，即使全部替换提示词、素材和参数，再次提交仍沿用原链并增加业务轮次。
- **创作链延续**：同页再次生成、继续编辑、基于结果重新生成、带入其他工具和从历史继续编辑沿用原链，业务轮次加 1。
- **自动重试**：系统失败自动重试不增加业务轮次；用户主动重新提交按来源关系判断。
- **同轮候选**：同一任务产生多张候选结果仍属于同一轮。
- **分母**：所选范围内首轮至少产生一个成功结果的去重 `creative_chain_id`。
- **分子**：分母中的创作链，其 `round_index=1` 的任一成功结果截至 `dataAsOf` 发生至少一次成功后续行为；同一链只计 1。
- **公式**：`firstRoundAdoptionRate = firstRoundAdoptedChains / creativeChains`。
- **排除**：首轮仅预览、首轮无成功结果、只有第二轮及以后结果发生采纳、系统失败自动重试本身。
- **空值**：`creativeChains=0` 时 `firstRoundAdoptionRate=null`。

### R-03 跨任务复用率

- **指标解读**：观察平台生成并沉淀的素材中，有多少再次进入其他任务形成复用。
- **可用生成素材分母**：在 `effectiveEndAt` 处于可用状态、来源可稳定追溯到平台生成 `result_id/source_task_id`、属于当前组织范围的去重 `resource_id`。
- **跨任务复用分子**：分母集合中的素材，在所选时间内至少一次成功绑定到与 `source_task_id` 不同的目标 `task_id`，按 `resource_id` 去重。
- **公式**：`crossTaskReuseRate = crossTaskReusedAssets / generatedAssets`。
- **复用次数**：`crossTaskReuseCount` 按幂等后的成功 `AssetUsageFact` 累计，不代替去重资产数。
- **目标功能筛选**：选择功能时只保留 `target_tool_key` 等于所选功能的跨任务使用事实；库存分母按上位 PRD 规则不随功能筛选变化。
- **排除**：同任务内部重复绑定、只预览、只下载、只加入素材库、素材选择失败、任务创建失败、来源任务无法识别的事实。
- **同源判断**：必须比较素材来源任务与目标任务，不得用不同页面、不同会话或不同人员替代“不同任务”。
- **空值**：`generatedAssets=0` 时 `crossTaskReuseRate=null`。

### R-04 平均后续使用结果积分

- **指标解读**：观察形成一个后续使用结果需要投入多少平台积分，是积分向有效产出转化的单位指标。
- **积分分子**：所选时间、组织和功能范围内，`credit_settled` 已完成结算的实际净扣减积分。
- **净积分**：`consumedPoints = settled_deduction - settled_refund`；同一流水按结算事实汇总。
- **结果分母**：与积分任务属于同一查询范围的 `followupUsedResults`。
- **公式**：`averagePointsPerFollowupResult = consumedPoints / followupUsedResults`。
- **任务关联**：积分必须通过 `task_id` 关联任务，再通过 `task_id/result_id` 关联成功结果及后续行为。
- **排除**：余额、申请额度、补发、未结算预估值、不扣费能力、无法关联任务的积分流水。
- **任务状态**：失败、部分成功、取消和重试按积分服务实际结算结果统计，不得按任务状态推算。
- **AI 提示词**：不产生生图积分，不进入积分分子和积分排行。
- **空值**：`followupUsedResults=0` 时 `averagePointsPerFollowupResult=null`。

### R-05 管理判断边界

- 四项指标只描述平台事实，不单独证明人工效率、业务 ROI、结果质量、积分浪费或人员绩效。
- 任何高低变化均需结合功能类型、任务复杂度、结果数量和组织使用场景复核。
- 本期不配置固定阈值，不生成“正常/异常”“高效/低效”标签。

## 10. 取数与聚合逻辑

### 10.1 公共处理顺序

1. 服务端读取当前用户角色与有效组织范围，校验 `organization_id`。
2. 按 `Asia/Shanghai` 生成查询开始、结束时间及 `effectiveEndAt`。
3. 读取查询范围内的任务和成功结果事实，保留任务创建时组织快照和来源功能。
4. 读取截至 `dataAsOf` 的成功后续行为，对 `result_id` 去重。
5. 按创作链和首轮规则聚合首轮成功链与首轮采纳链。
6. 按 `effectiveEndAt` 重建可用生成素材集合，再关联查询期间的跨任务使用事实。
7. 汇总与当前任务范围关联的积分结算净扣减。
8. 计算比率和单位值；所有分母为 0 的结果返回 `null`。
9. 返回相同 `aggregationVersion`、`dataAsOf` 和数据质量状态。

### 10.2 逻辑数据集

| 逻辑集合 | 过滤与去重 |
|---|---|
| `successful_results` | 结果生成时间在周期内；来源任务组织和功能符合筛选；`result_status=SUCCESS`；按 `result_id` 去重 |
| `successful_adoptions` | `successful_results` 中截至 `dataAsOf` 至少一次 `action_status=success` 的结果；按 `result_id` 去重 |
| `first_round_chains` | `successful_results.round_index=1`；按 `creative_chain_id` 去重 |
| `first_round_adopted_chains` | `first_round_chains` 中首轮成功结果存在成功后续行为；按 `creative_chain_id` 去重 |
| `available_generated_assets` | `effectiveEndAt` 状态可用、来源为平台成功结果、所有人组织符合筛选；按 `resource_id` 去重 |
| `cross_task_used_assets` | 分母集合中，周期内存在成功 `CROSS_TASK_REUSE` 且目标任务不同于来源任务；功能筛选作用于目标功能；按 `resource_id` 去重 |
| `net_consumed_points` | 当前任务范围的已结算扣减减已结算退回；按积分流水幂等 |

### 10.3 计算公式

```text
successfulResults = count(distinct successful_results.result_id)

followupUsedResults = count(distinct successful_adoptions.result_id)
followupUseRate = followupUsedResults / successfulResults

creativeChains = count(distinct first_round_chains.creative_chain_id)
firstRoundAdoptedChains = count(distinct first_round_adopted_chains.creative_chain_id)
firstRoundAdoptionRate = firstRoundAdoptedChains / creativeChains

generatedAssets = count(distinct available_generated_assets.resource_id)
crossTaskReusedAssets = count(distinct cross_task_used_assets.resource_id)
crossTaskReuseCount = count(idempotent cross-task AssetUsageFact)
crossTaskReuseRate = crossTaskReusedAssets / generatedAssets

consumedPoints = sum(settled deductions) - sum(settled refunds)
averagePointsPerFollowupResult = consumedPoints / followupUsedResults
```

聚合层必须保留原始计数，前端不得只接收百分比后反推分子和分母。百分比显示精度沿用页面现有格式化规则，接口返回原始数值。

## 12. 状态、边界与异常

### 12.1 页面与接口状态

| 状态 | 枚举 | 进入条件 | 页面表现 |
|---|---|---|---|
| 加载中 | `LOADING` | 首次进入或切换筛选 | 保留骨架，不展示旧条件数值 |
| 成功 | `SUCCESS` | 查询完成且有记录 | 展示四项指标 |
| 空数据 | `EMPTY` | 查询成功但当前条件无记录 | 展示空状态；不展示全 0 指标组 |
| 查询失败 | `ERROR` | 接口失败、超时或数据校验失败 | 清空旧数字，展示重试 |
| 无权限 | `FORBIDDEN` | 无角色或组织越权 | 隐藏数据并提示无权限 |
| 数据未就绪 | `NOT_READY` | 关键事实或关联未通过验收 | 展示统计起点，不展示模拟值 |

### 12.2 边界与异常

| 场景 | 数据处理 | 页面处理 |
|---|---|---|
| 同一事件重复投递 | 按事件 ID 或业务唯一键幂等 | 用户无感 |
| 同一结果多个成功动作 | 动作可分别保留；后续使用结果按 `result_id` 只计 1 | 展示去重分子 |
| 下载点击但文件失败 | 不写成功事实 | 指标不变化 |
| 同次历史继续编辑与结果继续编辑 | 只生成一条后续使用事实或聚合去重 | 指标不重复 |
| `result_id` 无法关联任务 | 不进入需要组织、功能或积分关联的指标；记录质量警告 | 对应指标 `--` 或整体 `NOT_READY` |
| 创作链或轮次缺失 | 不使用任务数替代 | 首轮直接采纳率不可用 |
| 素材来源任务缺失 | 不推断跨任务 | 跨任务复用率不可用 |
| 资源历史状态缺失 | 不用当前库存倒推历史 | 跨任务复用率 `NOT_READY` |
| 积分无法关联任务 | 不推算单位积分 | 平均后续使用结果积分 `--` 或主题不可用 |
| 组织未知 | 合法公司事实可保留；不进入部门排行 | `warnings` 返回数量 |
| 权限在页面打开后撤销 | 下一次查询服务端拒绝并清空数据 | 进入无权限状态 |
| 网络中断 | 不用缓存旧值覆盖新条件 | 展示错误和重试 |

## 13. 历史数据与兼容

1. 新字段和新事实从迁移、埋点部署及数据验收后的 `earliestAvailableAt` 生效。
2. 旧事实缺少组织、创作链、来源任务或资源所有人时，不得自动填默认值或按当前数据回写历史。
3. 2026-07-30 平台快照只能作为独立历史证据，不得拼入本指标真实趋势或分子分母。
4. 后续使用结果和首轮采纳允许因查询时点前新增成功后续行为而重算历史生成周期。
5. 资源库存历史必须来自状态流水或可证明的等价事实，不能使用查询时当前状态倒推。
6. 物理迁移必须向前兼容；回滚方式、索引和数据回填策略沿用目标仓库规范。

## 16. 验收标准

| 编号 | 关联规则 | 前置条件 | 操作步骤 | 预期结果 | 类型 |
|---|---|---|---|---|---|
| AC-01 | R-01 | 同一成功结果有下载、编辑、入库三个成功动作 | 查询管理关注项 | 成功结果计 1，后续使用结果计 1 | 去重 |

### 18.4 最低自动化测试

- 单元测试：四项公式、分母为 0、结果去重、首轮链、创作上下文重置、同页全部替换输入、系统自动重试、净积分、跨任务判定。
- 幂等测试：任务、结果、积分、后续行为、资产使用和资源状态重复投递。
- 契约测试：查询字段、`managementFocus` 全字段、`null`、`dataAsOf`、`aggregationVersion`、质量状态。

- 历史测试：调岗后查询历史组织、后续动作延迟更新、素材停用前后库存。
- 前端测试：三筛选联动、四张卡、主题跳转、加载/空/错误/无权限/未就绪。

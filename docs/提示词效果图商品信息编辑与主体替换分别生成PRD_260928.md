### 1. 提示词库｜新增：用效果图帮助判断版式

1. 提示词内容下方增加“效果图（可选）”，每条提示词支持 0～3 张。
2. 编辑时维护图片与顺序；浏览、审批及工作台选词时可查看效果图。
3. 效果图仅用于理解版式，复制或应用提示词仍只使用正文。

### 2. 商品学习｜修复：识别结果支持编辑并真正用于后续生成

1. “确认商品信息”步骤允许修改识别出来的商品信息，沿用已有原型。
2. 提交后以用户确认后的信息生成还原规格并保存商品档案，避免旧识别值覆盖修改。
3. 补齐保存失败、返回修改、再次识别和历史版本的验收。

### 3. 主体替换｜优化：一张目标商品图对应多张场景，分别生成

1. 图一是目标 B 商品原图，图二及以后是含 A 商品、需要替换的场景图。
2. 每张场景图搭配同一张 B 商品图，独立生成一张替换结果。输入总数为 N 时，目标结果数为 N−1。
3. 保留主体替换既有处理能力；成功图保留，失败场景单独重试，禁止输出拼接图。

### 2.2 页面与交互

| 页面 / 区域 | 操作与反馈 | 边界 |
|---|---|---|
| 新建/编辑，正文下方 | “效果图（可选）”；计数 `已添加 x/3 张`；添加、替换、删除、排序、设首图 | 满 3 张禁用继续添加，但允许替换；一次替换只选 1 张 |
| 列表 | 首张作缩略图；点击按既有详情/预览行为查看 | 无图保留既有文本卡片；不引入新筛选、排序或分页规则 |
| 详情、提交确认、审核 | 按顺序显示全部效果图并支持大图查看 | 按当前资源及审批快照展示，不混用其他版本图片 |
| 工作台提示词选择器 | 看效果图后选择提示词，回填正文 | 查看图片不触发应用；应用不新增参考图 |
| 大图预览 | 沿用现有预览关闭、切换及键盘行为 | Esc 先关图片预览，不同时关闭底层编辑/选择弹窗 |

提示文案：超量“每条提示词最多上传 3 张效果图”；失败“图片上传失败，请重试”；无图状态“添加效果图，帮助了解提示词的版式效果”。格式和大小提示须与真实上传配置一致。

### 2.4 状态、数据与责任

以下状态及接口字段名为业务建议命名，待技术映射；不得直接照搬原型 Data URL 作为生产存储方案。

| 状态 | 页面表现 / 可操作项 | 异常处理 |
|---|---|---|
| `EMPTY` / `READY` | 0 张 / 1～3 张，允许编辑与合法保存 | 无图不是错误 |
| `UPLOADING` | 显示上传中，禁用保存及冲突操作 | 上传失败回到可编辑状态，保留此前成功图片 |
| `SAVING` | 禁用重复提交 | 失败保留当前草稿、展示重试提示；不能显示保存成功 |
| `SAVED` | 列表与详情使用已保存版本 | 刷新/重新进入可回读；图片加载失败显示占位与重试，正文仍可用 |

| 对象 / 字段 | 类型 / 必填 | 范围、默认与校验 | 语义及兼容 |
|---|---|---|---|
| 提示词 `effectImages` | 图片引用数组 / 否 | 0～3 项；默认 `[]`；服务端同样校验 | 新增持久化字段；旧记录缺失按 `[]` 读取 |
| 图片引用 `id` | 字符串 / 是 | 沿用文件服务 ID 长度及格式，无手工默认值 | 唯一识别引用，不能仅用数组下标识别 |
| 图片引用 `src` | 可访问资源引用 / 是 | 沿用文件访问策略，须可解码且有权读取 | 原型名；生产可映射为文件 ID/受控地址，不持久化临时失效链接 |
| 图片引用 `name` / `size` | 元信息 / 沿用文件对象 | 文件服务返回；格式、长度沿用，显示值为空时不阻断正文 | 原型同名属性只用于展示，不据显示字符串校验大小 |
| 图片顺序 | 数组顺序 / 有图时是 | 首项为首图；删除、替换、排序后不超过 3 项 | 审批快照与详情一致；替换保持原位置 |

前端复用图片队列、预览与提示词选择器；资源服务负责上传、图文保存、排序及权限；审批服务携带同版本图片引用；AI 服务无新职责。列表查询/分页/筛选沿用已有规则，增加图片字段不能改变资源可见范围。旧客户端读写必须保留未认识的图片字段，不能因未传字段清空已有附图；实际兼容策略由技术方案确定。

| PL-R-03 | PL-CHG-02 | 下一步先完成校验与保存，再启动还原；保存失败不跳步、不发起任务，保留编辑值；重复点击不重复创建任务 | 商品智库 PRD 的事实→还原及幂等任务要求 |

| PL-R-05 | PL-CHG-02 | 本轮生成后再次修改信息，不改写已运行/已完成任务输入；下一轮使用新值并保留旧快照。最终档案使用运营确认对应版本的信息 | 商品智库 PRD 版本与历史规则 |
| PL-R-06 | PL-CHG-01、PL-CHG-02 | 必填、选项、长度等沿用字段原校验；非必填项允许清空并标明待补充；不能将空值改回旧识别值。审批中及已确认共享商品沿用修订权限 | 商品智库 PRD；不扩大权限与生命周期 |

交互：编辑时直接显示当前值；字段不合法在对应项提示原因；提交过程中禁用重复进入下一步；保存错误文案“商品信息保存失败，请重试”；新识别建议与人工值冲突时提示“已有人工确认信息，请核对后再修改”。沿用当前“确认”等动作，不新增独立编辑页。

### 3.3 数据、状态与 AI 输入契约

引用商品智库 PRD 既有 `fact_items`、`restoration_spec`、商品版本和审计结构，不另造一套事实模型。下表子字段为业务语义，物理命名待技术映射。

| 对象 / 字段 | 类型 / 必填 | 范围、默认及校验 | 保存与版本要求 |
|---|---|---|---|
| `fact_items` | 对象数组 / 是 | 沿用既有结构和字段清单；识别后作为初始值 | 前端不得只改显示文本而不更新实际提交对象 |
| 事实项标识、值 | 标识 + 现有值类型 / 按原字段 | 标识不可编辑；长度、选项、必填沿用原约束；空值不可回退旧值 | 编辑值按稳定标识更新，不能按显示顺序错配字段 |
| 事实状态 | 枚举 / 是 | `CONFIRMED/INFERRED/MISSING`，沿用原结构；不自动确认未查看的推断 | 确认操作对应状态改变；清空非必填项体现缺失 |
| 来源及关联证据 | 原有来源对象与图片引用 / 按原结构 | 人工修改与 AI 识别可区分；证据 ID 沿用，不允许捏造 | 保留原始识别与人工修改的追溯能力，沿用审计策略 |
| `restoration_spec` | 对象 / 提交还原时是 | 无独立业务默认值，从保存成功的本轮事实生成 | 固定商品/事实版本，与本轮任务共同保存 |

页面状态建议映射为 `EDITING/SAVING/SAVED/SAVE_FAILED`。识别未完成时沿用原加载态；保存失败可编辑重试；权限失效时阻止写入并保留当前可恢复输入。离开/刷新沿用商品草稿机制：已保存修改必须恢复，未保存内容不承诺自动保存；多端冲突不得以旧值静默覆盖新确认版本，复用现有版本冲突提示。

本次不变更识别或还原模型，只修复人工输入生效链路：

| AI 契约项 | 要求 |
|---|---|
| 事实优先级 | 已人工确认的当前值优先于旧识别输出；原图提供视觉证据，冲突应提示核对，不以模型猜测偷偷覆盖人工值 |
| 下游输入 | 读取本轮已保存事实及允许推断项、参考图片，按原 PRD 装配还原规格；不能重新读取旧识别缓存替代快照 |
| 业务 Prompt 语义 | “依据本轮已确认商品事实和参考图还原商品。人工确认值是本轮约束；未知项保持未知，不补造不可见结构；冲突或输入不足按原流程反馈。” |
| 输出与失败 | 沿用还原输出与质量门禁；输入保存/版本校验失败时不调用模型、不创建生成扣费 |
| 示例 / 反例 | 用户将主色从白改为米色，本轮规格及档案应为米色；反例是页面显示米色但模型请求、返回后或档案仍为白色 |
| 模型与兼容 | 沿用当前识别/还原模型、输入格式、尺寸和数量限制；具体版本及请求映射由开发核实，不新增模型采购或能力承诺 |
| 重试 / 人工接管 | 保存失败重试保存；识别或还原失败沿用原 PRD 的重试、人工补充和纠错流程；不为本次修改新增生成次数 |

责任：前端接通既有编辑控件、校验和保存反馈；商品服务持久化事实及版本；还原任务读取该版本快照；模型适配层不得覆盖人工约束。权限、历史、积分沿用商品智库和平台规则，字段编辑本身不计作 AI 生成。

### 3.4 验收、证据与指标

| 验收 | 关联规则 | 前置条件与操作 | 可观察结果 |
|---|---|---|---|
| PL-AC-01 | PL-R-01、PL-R-02 | 完成识别，修改一个已有值、补全待补充项、确认一个推断 | 页面可编辑；三类值及确认状态正确，证据查看仍可用 |
| PL-AC-02 | PL-R-03、PL-R-04 | 修改主色后进入还原，在测试环境检查实际保存对象与任务输入 | 两者均为新主色；旧识别值不出现在对应生效字段 |
| PL-AC-03 | PL-R-04 | 保存后返回确认页、刷新/重新打开草稿，再次发起识别 | 已保存人工值不丢失；再次识别不静默覆盖它 |
| PL-AC-04 | PL-R-03 | 模拟保存失败，重复点击下一步后重试 | 停留原步骤、保留编辑内容；失败期间无还原任务，成功后仅创建一次 |
| PL-AC-05 | PL-R-06 | 输入非法必填值；另清空一个非必填字段 | 非法必填阻止下一步并定位字段；非必填可按缺失提交，不恢复旧值 |
| PL-AC-06 | PL-R-05 | 用版本一生成后返回改值，创建版本二并运营确认，回看旧任务 | 旧任务保留版本一；新任务和对应最终档案采用版本二 |
| PL-AC-07 | PL-R-06 | 查看者、审批中商品、已确认共享商品分别尝试直接写入；有权用户走修订 | 非法写入被服务端阻止；合法修订沿用原流程，不覆盖旧共享版本 |

证据：原型 FactsEditor 已有 `value/onChange` 与确认操作，既有商品智库 PRD 已要求修改信息；尚未获得真实线上请求、持久化与生成输入证据。本轮不修改原型。

验收样本至少覆盖已确认/推断/缺失三类事实、单字段与多字段修改、保存失败和历史版本；产品核对业务值，测试比对保存与任务输入，开发提供脱敏追踪证据。AI 图像质量继续用原商品智库标准，不能只凭生成图片观感证明传值正确。

指标：统计确认页人工修改率、修改后保存失败率、人工确认值与本轮任务输入一致率。新增链路验收要求测试样例不存在字段丢失或旧值覆盖；生产目标与基线待采集，不虚构提升比例。

## 4. 主体替换分别生成（SR）

### 4.1 变更与用户流程

| 变更 | 内容 | 来源 |
|---|---|---|
| SR-CHG-01 | 主体替换支持目标商品图 + 多场景的分别生成语义 | 用户最终确认 |
| SR-CHG-02 | 按场景拆分调用、独立结果、禁止拼接 | 用户最终确认；批量改图效果不足的用户反馈 |
| SR-CHG-03 | 场景与结果关联、失败单张重试、历史兼容 | 为分别生成补齐的交付与验收边界；复用现有任务/结果能力 |

角色示例：B 商品图 + A 商品场景 1 + A 商品场景 2 + A 商品场景 3 + A 商品场景 4 → B 商品场景结果 1、2、3、4，共 4 张。目标商品图不是待替换场景，不单独产出结果。

流程：进入主体替换的分别生成操作 → 图一上传目标 B 商品原图 → 图二及后续上传待替换场景 → 核对角色、场景数量与预计结果数 → 提交 → 各场景分别执行替换 → 查看按输入顺序关联的结果 → 失败场景按原输入单独重试 → 使用既有预览、下载和结果操作。

本 PRD 固定“分别生成”的处理语义，不指定新增开关的位置或改动原型布局。旧模式如何与该操作并存、默认进入哪一模式，见第 6 章产品待确认项；不得直接把所有历史多图任务的图一含义翻转。开发可先评估并实现独立任务协议，模式入口确定后再接入。

### 4.2 页面说明与核心规则

线上接入时，分别生成上下文中的角色说明必须改为：**“图一为目标商品原图，图二及后续为待替换场景图，每张场景图分别生成一张结果。”** 此为开发文案要求，本轮不改原型。上传项区分“目标商品”“场景 1/2/…”；预计结果显示为“将分别生成 S 张”，S 为有效场景数。

| 规则 | 关联变更 | 处理与边界 | 状态 / 来源 |
|---|---|---|---|
| SR-R-01 | SR-CHG-01 | 图一提供唯一目标 B 商品外观来源；图二及以后各自为待编辑底图，含需被替换的 A 商品。最少输入 2 张，即 1 张 B + 1 张场景 | 已确认：用户；最小输入为该角色规则推导 |
| SR-R-02 | SR-CHG-02 | 输入 N 张，拆为 N−1 个场景项；每个场景独立处理“该场景 + B 商品图”，每个场景只对应 1 张最终结果。不把全部场景一次送入单张合成请求 | 已确认：用户分别生成、不拼接；执行边界 |
| SR-R-03 | SR-CHG-02 | 本分支结果目标数由场景数计算；现有生成张数 count 不再乘到每个场景上，也不能用 count 代替任务拆分。处理中候选或重试不能增加逻辑结果位 | 已确认规则的数量闭环 |
| SR-R-04 | SR-CHG-02 | 沿用主体替换的排版、身份与替换处理链路；只替换对应场景的商品，保留场景人物、背景、构图、动作与非目标元素，适配合理遮挡、接触、透视和光影 | 用户选择主体替换的目的及业务质量要求；效果需真实验证 |
| SR-R-05 | SR-CHG-03 | 按原场景顺序展示结果位，完成先后不改变对应关系；部分成功保留成功图，失败位展示原因与重试入口；单张重试仅使用同一 B 图和该场景的冻结输入 | 分别生成必要的异常与结果边界 |
| SR-R-06 | SR-CHG-01、SR-CHG-03 | 提交前删除/排序/替换必须重新校验角色与计数；目标图删除后不能悄悄将场景变成 B 图。提交时冻结模式、目标图、场景 ID/顺序和参数，后续编辑只影响新任务 | 角色稳定性与历史兼容要求 |
| SR-R-07 | SR-CHG-03 | 新任务保存明确的分别生成模式和场景映射；旧任务缺失新模式字段时按旧协议解释，旧结果与正在执行的旧任务不迁移图片角色 | 当前原型旧语义与新规则差异的兼容要求 |
| SR-R-08 | SR-CHG-03 | 完成数只统计通过输出结构校验的场景结果；子任务幂等，刷新、回调重复、失败重试都不能重复记成功或对同次成功重复扣费 | 平台任务规则及本次拆分要求 |

输入格式、单图大小、总数上限沿用经核实的主体替换生产配置，不采用原型演示上限；业务案例 3～5 张场景不等于数量上限。上传重复图片沿用现有处理策略；若允许重复，则各上传项按独立场景 ID 关联，不能以同内容自动合并造成结果数减少。提交后改变 B 商品或场景属于新任务，不能冒充旧失败项重试。

### 4.3 AI 处理契约

| 契约项 | 要求 |
|---|---|
| 输入与事实源 | 每个子任务明确传入目标 B 商品图、当前唯一场景图、原有替换要求及有效参数；B 图提供身份，场景提供位置、构图、人物与环境 |
| 优先级 | 商品身份遵从 B 图；布局、人物、动作、背景遵从当前场景；补充文字只能细化替换，不能要求拼接或覆盖已锁定身份与场景 |
| 适配 | UI 图一不等于模型接口中的待编辑原图参数。开发必须将当前场景映射到编辑底图、将 B 图映射到商品身份参考，按供应商实际接口装配 |
| 处理责任 | 应用/任务层拆场景和关联结果；模型链路复用主体替换能力处理单场景。不能依赖一句“不要拼图”的提示词代替拆分 |
| 输出结构 | 每个场景一个可独立访问的图片结果及该场景的状态/错误；结构化业务关联由应用封装，不要求图像模型凭空返回平台 ID |
| 输出成功 | 文件可读、数量正确、场景关联正确是结构成功的必要条件；接口 200 或供应商返回一张图不自动等于业务验收成功 |
| 质量门禁 | 单图检查 B 身份、替换完整、场景保留、遮挡/接触合理、无跨场景拼图；批次检查一场景一结果、无漏图、错配或其他场景混入 |
| 禁止项 | 不把 B 原图当第一张待改场景；不把场景当多个商品参考合成；不拼为宫格/长图；不输出拼图再裁切；不凭空补造 B 商品关键结构 |
| 失败处理 | 缺输入、不支持的模型能力、文件不可读、数量或映射错误需报错，不伪造成功；质量问题沿用现有质检/纠错能力，未具备自动质检时由人工验收并允许原有返修流程 |
| 重试与停止 | 系统限流/超时重试次数与时限沿用平台配置，开发回填实际规则；达上限停止该项并保留错误，禁止无限重试。用户单张重试保留其他成功图和本项历史记录 |

业务 Prompt 语义模板（供开发适配现有主体替换链路，不指定供应商请求格式）：

> 任务：将当前场景中的 A 商品替换为目标参考图中的 B 商品，只输出当前场景的一张完整图片。目标商品图只用于确定 B 商品外观与身份；当前场景图决定构图、人物、动作、背景和商品所在位置。保留非目标元素，按场景适配 B 商品的合理透视、遮挡、接触关系与光影。不要拼接、宫格、组合多场景，不得直接返回目标商品原图或重绘其他场景。输入不足或目标无法判断时按任务失败契约反馈，不用编造商品结构补全。

正例：4 个场景创建 4 个逻辑子任务，分别得到 4 张对应场景的 B 商品结果。反例：一次将 B 图和 4 张场景输入单张输出请求，只返回 1 张四宫格；即使四宫格视觉质量好仍验收不通过。

### 4.4 模型能力与输入输出兼容

| 能力 | 本期要求 | 已知事实 / 技术核实 |
|---|---|---|
| 模型 / 版本 | 使用主体替换现有有效链路；不切换为批量改图链路 | 具体模型、版本及内部排版步骤由开发核实；不宣称已获得效果提升 |
| 输入类型与数量 | 每子任务至少可区分 1 个待编辑场景和 1 个目标商品参考 | 上传批次上限与模型单请求限制分别核实；不将批次场景数误当单请求图片数 |
| 格式、尺寸、比例 | 沿用现有主体替换支持范围；以当前场景构图为保留目标 | 实际转换/缩放/比例适配由开发列出，不能为满足固定尺寸把多图拼起来 |
| 输出 | 每子任务 1 个最终场景结果位 | 供应商若返回候选集合，内部按既有采用策略确定结果，不扩成额外场景 |
| 降级 | 模型不支持必要输入角色时阻止提交并说明原因 | 不允许静默降级为拼接、单张随机场景或批量改图 |

| 输入 / 消费方 | 兼容规则 |
|---|---|
| 新分别生成任务 | 按 B 图 + 场景数组解释，保存新模式和映射 |
| 旧单场景/多参考任务与历史 | 保持图一原图、后续参考的旧协议，不逆转，不重新拆分 |
| 商品智库选择 | 与“图一目标商品”有来源重叠；本需求只确认图片上传语义，两者并存/互斥或回填方式待产品确认，不能静默用所选商品覆盖图一 |
| 未识别新模式的旧客户端 | 不允许按旧模式继续编辑并覆盖新任务；安全展示结果或提示进入支持该模式的入口，具体兼容方案由技术评审确定 |
| 历史、下载、素材操作 | 复用已有入口，按场景结果 ID 操作；下载独立图片，不将批次再拼成一张；既有批量下载能力若存在则复用，不另立下载模块 |
| 权限与计费 | 输入、任务、结果均校验当前用户权限；按实际生成/重试项接现有积分机制，不能只按 1 个批次估算成 1 张；价格和失败退款策略待技术核实 |

### 4.5 状态与异常

以下枚举为建议命名，待技术映射，沿用任务服务现有能力。

| 状态 | 进入条件 | 用户反馈与操作 |
|---|---|---|
| `DRAFT` / `INVALID` | 未提交 / 缺 B 图、无场景、超限或上传未完成 | 标清角色及原因，阻止生成；修改或重新上传 |
| `SUBMITTING` | 正在创建批次与场景项 | 禁止重复提交；失败保留输入，不显示已生成 |
| `QUEUED` / `RUNNING` | 排队或有场景执行中 | 展示各项进度；允许按现有任务机制离开，返回可恢复 |
| `SUCCESS` | 所有场景项成功 | 显示独立结果；沿用预览、下载和后续操作 |
| `PARTIAL_SUCCESS` | 批次结束，至少一项成功且有未成功项 | 保留成功结果，失败位可单张重试；取消项单独标记 |
| `FAILED` | 无成功结果且所有执行项失败 | 显示逐项原因，可按原输入重试失败项 |
| `CANCELLED` | 沿用平台取消能力，未完成项已终止 | 不新增取消入口；若平台已支持取消，保留此前成功结果，停止未执行项，退款沿用现有规则 |

子任务使用各自 `QUEUED/RUNNING/SUCCESS/FAILED/CANCELLED`，父任务聚合状态不得覆盖子任务事实。等待中/执行中有成功图时仍显示批次进行中；仅终止后聚合为完成、部分成功、失败或取消。

| 异常 | 处理 |
|---|---|
| B 商品图不可读或权限失效 | 共享输入无效，阻止尚未开始的相关场景；已成功结果保留，不尝试用任意场景代替 B 图 |
| 个别场景无效 / 超时 / 限流 | 该项展示失败或按现有重试策略处理，不清空其他成功结果 |
| 返回图片数/场景关联错误 | 结构校验失败；不能按成功完成数展示，不可把同一张拼图复制到多个结果位 |
| 替换残留、身份错误或场景变形 | 属质量不合格；人工可标记并单项返修。自动检测如何接入由现有质检能力决定，不能声称本轮已新增视觉质检服务 |
| 离开、刷新、重复回调 | 通过既有任务历史恢复场景映射；幂等处理回调，不新建一批、不重复计费 |
| 场景中有多个不同商品且目标不明确 | 按现有主体替换消歧/提示失败机制处理，不擅自扩大到所有物体替换 |

### 4.6 数据与责任边界

下表为业务字段建议，物理字段、长度和已有字段映射待技术确认；沿用原任务 ID、权限、时间、费用和文件对象。

| 对象 / 字段 | 类型 / 必填 | 范围、默认、校验 | 快照与兼容 |
|---|---|---|---|
| 批次 `generation_mode` | 枚举 / 新任务是 | 新值建议 `PER_SCENE`；无字段按旧模式解释，禁止默认把旧任务视为分别生成 | 显式区分新旧角色语义 |
| 批次 `target_image` | 现有图片引用 / 本模式是 | 恰好 1 张，无默认；校验权限、可读与格式 | 提交时冻结 B 图版本 |
| 批次 `scenes` | 场景项数组 / 是 | 至少 1 项；上限=核实后的批次图片上限−1；无默认 | 冻结场景顺序和稳定 ID |
| 场景 `scene_id` / `scene_index` | 字符串 / 整数，均是 | ID 唯一、长度沿用任务子项 ID 规则；顺序 1～S，禁止重复下标 | 不能以完成时间决定排序 |
| 场景 `image` | 现有图片引用 / 是 | 沿用图片对象与上传校验，无默认 | 子任务只能消费当前场景及共享 B 图 |
| 子任务关联 / 输入快照 | 现有任务引用及对象 / 提交后是 | 关联批次、场景、B 图、参数、模型及实际请求版本 | 重试沿用冻结输入；改输入创建新任务 |
| 结果与状态 | 现有结果引用 / 成功时是；状态枚举 / 是 | 每场景 1 个当前结果位；初始排队，失败无成功图片 | 保留既有版本与尝试记录，不把失败占位当图片 |
| `expected_count` | 派生整数 / 展示与校验使用 | 始终为 S=N−1，服务端计算，不能信任任意前端 count | 成功数、失败数、待执行数分开记录 |

责任：前端明确角色、结果数量与逐项状态；任务服务拆分、调度、幂等和历史快照；AI 适配层保持主体替换处理并正确映射两类图片；文件/积分/素材等公共服务沿用现有能力，仅扩展场景项关联。并发、队列、保留时长、超时与限流沿用平台配置，技术评审给出实际值。系统自动重试、内部质量候选、用户主动重试须区分尝试与业务结果，不以内部调用次数随意扩大用户看到的结果数或费用。

| SR-AC-02 | SR-R-01 | 仅上传 B 图尝试提交；再补 1 张场景 | 第一次阻止提交并提示缺场景；第二次目标结果数为 1 |

质量样本：使用经授权的真实 B 商品原图，配一组 3～5 张 A 商品买家秀；包含近景/远景、人物接触、遮挡、复杂背景。另用 1 张场景做最小边界，用生产上限做最大边界；本轮未提供完整原图素材包，需在联调前补齐。

验收方法：每个场景并排查看原图、B 图和结果，逐项标记商品身份、替换完整、场景保留、遮挡与光影、无拼接、映射正确。身份错误、拼接、漏图和错配属于阻断通过的问题；产品/业务验收人逐图确认，测试保存场景 ID、版本、输出文件与判定，开发提供子任务映射及脱敏请求证据。具体人员待排期指派；不虚构质量通过率，修复后的验收集须全部满足对应通过条件。

状态与证据：仅有用户反馈、截图和当前原型代码对照；本轮未改原型，未运行真实主体替换、未验证底层质量提升。现有原型的模拟结果不能作为 SR-AC 通过证据。

指标：按场景统计任务成功率、无拼接率、业务采用率；按整组统计提交至全部场景结束的耗时与人工操作次数。区分结构成功与视觉采用，单独记录失败重试；基线/目标值待真实样本及上线数据采集，不能用批次成功率掩盖单项失败。

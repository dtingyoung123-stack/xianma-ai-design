## 1. 背景与目标

### 1.1 当前问题

1. 主体替换结果存在局部瑕疵时，用户需要整张重新生成或重新上传到其他工具，增加重复操作、生成等待和积分消耗。
2. 不同 AI 工作台的提示词模板入口不一致，运营需要记忆不同页面的使用方式，现有提示词资产无法稳定复用。
3. 图片大图预览到达最后一张后无法继续切换，用户比较第一张与最后一张时需要退出或反向翻页。
4. 不同下载入口采用不同文件名规则，结果图落地后难以识别、归档和批量交付。

### 1.2 本次目标

- 减少主体替换结果的整图重做，让用户能在不重复上传的前提下继续处理局部问题。
- 将提示词模板沉淀为全平台 AI 创作输入的统一公共能力，提高个人、团队和公共提示词复用率。
- 统一图片预览切换行为，降低多结果对比成本。
- 统一图片文件命名，提高运营下载后的识别、整理和交付效率。

### 1.3 成功判断

- 用户可从主体替换的任一成功结果直接进入局部修改，无需先下载再上传。
- 本期范围内所有可编辑 AI 提示词输入均显示同名、同位置、同交互的“提示词模板”入口。
- 同一图片组内可从最后一张继续切换到第一张，也可从第一张反向切换到最后一张。
- 任一图片下载入口得到的文件名均与页面展示的图片名称一致，并能处理空名称、非法字符和同名文件。

本期不设缺少基线依据的数值 KPI。上线后可通过“局部修改使用次数、提示词模板选择次数、图片下载次数和重复生成轮次”观察使用效果，但不得在埋点未完成前编造效果数据。

## 4. 总体用户流程

### 4.1 主体替换局部修改

1. 用户完成主体替换任务并得到一张或多张成功结果。
2. 用户在目标结果卡或该结果的大图预览中点击“局部修改”。
3. 系统将当前结果图作为待编辑图片带入现有产品微调/区域编辑链路，不要求用户下载或重新上传。
4. 用户圈选需要修改的区域，填写修改要求，也可通过“提示词模板”选择已有提示词。
5. 用户提交后，系统按现有生成任务规则处理，并保留来源结果与新结果之间的关系。
6. 用户可查看、下载或继续编辑新结果；原主体替换结果不得被覆盖或删除。

### 4.2 提示词模板

1. 用户进入第 6.2 节标记为“接入”的 AI 工作台。
2. 提示词输入组件右上角显示“提示词模板”，其右侧继续保留现有“AI 润色”等页面操作。
3. 用户打开模板选择器，在个人提示词、团队提示词、公共提示词和灵感广场之间切换，搜索、筛选并预览正文。
4. 用户选择一条模板并点击“使用此模板”。
5. 系统使用模板正文直接替换提示词输入框的当前内容并关闭选择器，不区分输入框原本为空或非空。
6. 回填后的提示词仍可继续编辑、润色、清空和提交；用户在使用前取消或关闭选择器时，原输入内容保持不变。

### 4.3 大图循环预览

1. 用户在图片列表、素材列表或结果列表中打开任一图片的大图预览。
2. 用户点击上一张或下一张，系统按当前图片组顺序切换。
3. 当前为最后一张时点击下一张进入第一张；当前为第一张时点击上一张进入最后一张。
4. 页码、图片名称、下载对象和其他当前图片信息同步更新。

### 4.4 下载命名

1. 用户从结果卡、大图预览、历史记录或批量导出触发下载。
2. 系统读取当前图片的展示名称并按第 8 节统一规则生成文件名。
3. 下载成功后，原图片对象、历史记录和页面展示名称保持不变。

## 5. 主体替换结果局部修改规则

### R-01 局部修改入口

- **规则状态**：本次确认方案。
- **触发条件**：主体替换结果状态为成功且结果文件当前可用。
- **入口位置**：每张成功结果卡的操作区，以及该结果的大图预览操作区。
- **按钮文案**：`局部修改`。
- 生成中、失败、取消或结果文件失效时不展示可点击入口；如页面需要保留入口用于解释，应禁用并展示明确原因。
- 多张结果必须逐张操作，点击哪张就带入哪张，不得默认带入第一张或最后一张。

### R-02 复用现有编辑能力

- 点击“局部修改”后复用产品微调已有的图片区域编辑、遮罩、提示词编辑、模型参数、生成任务和结果对照能力。
- 不要求用户重新选择素材或上传图片。
- 不新增主体替换专属遮罩编辑器、专属提示词选择器或专属大图组件。
- 页面跳转或同页承接由技术结合现有路由和真实接口决定，但最终用户流程、数据关系和验收结果不得改变。

### R-03 编辑范围

- 一期局部修改定义为：用户圈选一个或多个区域，并通过文字要求对所选区域重新生成。
- 未选区域作为保护区传入生成任务；系统不得主动将整图重做作为局部修改结果。
- AI 视觉结果无法仅凭前端保证像素级完全一致，技术方案必须传递原图和有效遮罩；具体模型一致性阈值待模型与测试方案确认，不在本文编造数值。
- 用户未完成有效圈选时，“开始局部修改”保持禁用，并提示“请先选择需要修改的区域”。

### R-04 取消、返回与原结果保护

- 用户在区域编辑器点击取消或关闭时，不创建新任务、不扣积分、不改变原结果。
- 用户返回主体替换页面后，原任务和全部结果保持原状态。
- 局部修改生成新结果，不覆盖原主体替换结果；历史记录必须能够追溯来源结果。

### R-05 任务、积分与历史

- 局部修改属于一次新的 AI 生成提交，积分预估、扣费、失败处理、重试和补偿沿用平台现有生图任务规则。
- 新任务沿用原创作链并增加业务轮次；系统自动失败重试不增加业务轮次。
- 新任务必须关联来源主体替换结果；进入产品微调或区域重绘历史时仍可追溯来源功能、来源任务和来源结果。
- 原任务或原结果后续删除、过期时，历史来源关系的处理沿用平台现有历史与文件保留规则；不得因本次需求另行复制长期文件。

### R-06 异常处理

| 异常场景 | 处理规则 | 用户可执行操作 |
| --- | --- | --- |
| 来源结果文件失效 | 不进入编辑器；明确提示结果暂不可用 | 返回结果列表或重新生成 |
| 带入编辑器失败 | 保留主体替换结果页状态，不创建任务 | 重试带入或关闭提示 |
| 遮罩保存失败 | 不允许提交生成 | 重新应用选区 |
| 生成失败 | 保留来源图、遮罩和提示词快照 | 按现有规则重试或退出 |
| 用户中途离开 | 沿用现有异步任务与历史恢复规则 | 从历史记录继续查看或编辑 |

## 6. 全局“提示词模板”规则

### R-07 名称与位置

- 公共入口统一命名为 `提示词模板`，不得在不同页面使用“选择提示词”“提示词选择”“模板库”等其他入口文案。
- 入口位于提示词输入组件标题区域右上角；同区域存在“AI 润色”时，顺序为“提示词模板”在左、“AI 润色”在右。
- 复用现有按钮图标、尺寸、颜色、悬停、焦点和禁用规范，不新增页面级特殊样式。
- 窄屏空间不足时，操作区允许换行到标题下方，但入口不得溢出、被裁切或与标题重叠。

### R-08 “全局”定义

“全局都需要”统一解释为：**平台内所有允许用户编辑并用于 AI 图片、视频或多模态生成的提示词、创作指令、修改指令输入，都必须接入“提示词模板”；普通业务文本、管理文本和只读提示词不接入。**

以下判断优先级适用于新增菜单：

1. 输入内容是否直接进入 AI 生成任务作为提示词或修改指令；是则接入。
2. 输入是否只是商品卖点、替换文字、评论、备注、审批原因、搜索条件或其他业务字段；是则不接入。
3. 输入是否只读或由系统自动合成且用户不能直接编辑；是则不接入。
4. 新页面存在多个提示词输入时，每个独立提交上下文分别接入；不得只在页面顶部放一个与输入关系不清的全局按钮。

### R-09 模板来源与权限

- 选择器固定提供四个扁平入口：`个人提示词`、`团队提示词`、`公共提示词`、`灵感广场`。
- 四个入口不得合并为“共享提示词”，也不得把灵感广场伪装为内部已验证内容。
- 个人提示词仅展示本人当前可用内容；团队提示词按现有组织可见范围返回；公共提示词对全部有效账号可见；灵感广场按现有来源和权限规则展示。
- 公共提示词展示“内部已验证”；灵感广场展示外部来源和“未验证”。
- 无权限来源页签禁用并提示“当前账号暂无权限”；前端隐藏或禁用不能替代服务端权限校验。

### R-10 选择器能力

- 选择器不提供编辑、删除、提交审核、取消申请或审批能力。
- 同一提示词同时出现在团队和公共入口时必须使用同一资源 ID；切换入口保持选择状态，不重复计数。
- 加载中不展示可操作内容；加载失败提供“重新加载”；空状态允许切换来源、调整筛选或关闭。

### R-11 模板直接回填

- 用户选择模板并点击“使用此模板”后，系统使用模板正文直接替换输入框的全部当前内容并关闭选择器；输入框原本为空或非空时规则一致。
- 本期不弹出替换方式二次选择，不提供追加、拼接或智能合并能力；相关能力待业务后续提出明确需求时再评估。
- 用户在点击“使用此模板”前取消或关闭选择器时，不回填模板，原输入内容保持不变。
- 选择模板后，用户可以继续编辑；后续编辑不改变原提示词库资产。
- 选择器的“清空模板”沿用现有公共选择器规则；不得删除提示词库中的原资源。

### R-12 页面已有参数保护

- 打开、取消或使用提示词模板不得重置图片、素材、场景、模型、比例、清晰度、数量、语言或其他页面参数。
- 模板正文超过目标输入现有最大长度时，系统不得静默截断；应阻止回填并提示目标输入的长度限制，具体上限沿用各页面现有规则。
- 模板标记“需要参考图”但当前页面没有参考图时，可回填正文，但必须展示“该模板建议配合参考图使用”，不得自动上传或补充图片。

## 7. 大图首尾循环切换规则

### R-13 循环范围

- 循环仅发生在用户打开大图时所属的当前图片组内。
- 图片组可以是当前输入队列、当前生成任务结果组、当前素材列表分组或当前历史结果组。
- 不跨任务、不跨分页、不跨筛选结果边界，也不自动请求下一页数据。
- 页面筛选、排序或数据刷新后，以当前可见组的新顺序为准；当前图片已不存在时关闭预览并提示“当前图片已不可用”。

### R-14 上一张与下一张

- 图片组数量大于 1 时显示上一张和下一张按钮。
- 当前为最后一张时点击下一张，切换到第一张。
- 当前为第一张时点击上一张，切换到最后一张。
- 其他位置按当前顺序正常加一或减一。
- 图片组只有 1 张时不显示切换按钮，页码显示 `1 / 1`。

### R-15 切换后的状态

- 切换后图片名称、序号、下载对象、颜色吸取对象及其他当前图片信息同步更新。
- 每次切换重置上一张图片的缩放、拖动位置、左右翻转、上下翻转和临时取色状态，避免状态误带到下一张。
- 单张图片加载失败时仍允许切换到上一张或下一张；失败图位置展示加载失败状态和重试入口。
- 关闭大图后返回原列表，原筛选、滚动位置和选中任务保持不变。

### R-16 交互一致性

- 所有业务页面优先复用公共 `ImagePreviewModal` 或统一后的等价公共组件，不得在页面内各自实现不同的首尾判断。
- 鼠标按钮必须完成循环切换。键盘左右键循环切换作为建议项，可在不改变输入焦点和无障碍行为的前提下同步实现。

## 8. 图片下载命名规则

### R-17 适用入口

统一命名规则覆盖：

- 生成结果卡单图下载；
- 大图预览下载；
- 历史记录单图下载；
- 素材详情中的图片文件下载；
- 批量任务中的单张结果下载；
- ZIP 批量导出包内的每张图片。

文档、PRD、表格、视频、音频和 ZIP 压缩包自身的命名不属于本次图片命名规则；压缩包内部图片必须遵守。

### R-18 文件名优先级

下载文件名按以下优先级取值，命中后停止：

1. 当前图片对象已保存的图片名称；
2. 页面当前展示的结果名称或素材名称；
3. 来源文件原始名称去除扩展名；
4. 回退名称：`{功能名称}-{序号}`。

不得优先使用请求 ID、存储对象 Key、随机 UUID、CDN 文件名或 URL 最后一段作为用户下载文件名。

### R-19 扩展名

- 文件名主体先移除已有扩展名，再根据实际下载文件格式补充扩展名，避免出现 `图片.png.webp`。
- 优先使用服务端文件元数据或响应 `Content-Type` 判断实际格式；无法取得时再使用可验证的文件 URL 扩展名。
- 无法判断格式时沿用平台现有图片下载兜底格式，不得把非 PNG 文件只改后缀伪装成 PNG。

### R-20 名称清洗

- 文件名中的 Windows 非法字符 `\\ / : * ? " < > |` 统一替换为短横线 `-`。
- 去除名称首尾空格、首尾句点和连续无意义空白。
- 清洗后为空时使用回退名称。
- 文件名长度上限及中文、英文、数字混排的截断规则由技术根据现有文件服务确定；截断时必须保留扩展名，不能产生空名称。

### R-21 同名与批量下载

- 同一次批量导出中出现同名图片时，按当前图片组顺序追加两位序号：`图片名称-01.ext`、`图片名称-02.ext`。
- 单图下载不为首个文件主动追加序号；同一文件重复下载后的本地重名处理由浏览器或操作系统负责。
- ZIP 包内文件名必须唯一，不得因同名覆盖或丢失图片。
- 下载命名只改变用户获得的本地文件名，不修改平台内图片名称、素材名称、历史记录或存储对象 Key。

### R-22 统一实现

- 大图预览、结果卡、历史记录和批量下载必须调用同一套命名规则或共享工具方法。
- 页面不得继续直接依赖浏览器从 URL 推断名称。
- 服务端以附件响应下载时，前端名称与 `Content-Disposition` 必须使用同一规则；出现冲突时以产品规则生成的图片名称为准。

- 本需求应作为一次跨模块增量实施，不拆成四套互不关联的页面逻辑。
- CHG-02～CHG-05 均以公共能力统一为优先；CHG-01 通过跨工具续作复用现有区域编辑能力。
